1.	Что такое репозиторий/коммит/ветка?
Репозиторий - это место, где хранятся, накапливаются и поддерживаются файлы вместе с историей их изменений.
Коммит - снимок состояния файлов проекта в Git в определённый момент времени.
Ветка - независимая линия разработки проекта, позволяющая изолированно писать новый код или исправлять ошибко, т.е. отдельно от основного проекта. По сути, просто перемещаемый указатель на один из коммитов.

2.	Какие бывают состояния файла в Git?
Untracked - новые файлы в директории, которые Git ещё не контроллировал.
Unmodified - файлы, которые уже есть в репозитории, и над которыми не было произведено изменений.
Modified - файлы под контролем Git, которые были изменены, но ещё не закоммичены.
Staged - файлы, подготовленные для коммита.

3.	Какие основные команды Git?
git add filename - Добавлена файла в stage.
git rm filename - Перевод файла в stage в разряд удалённых.
git reset HEAD filename - Сброс текущего файла из stage с сохранением изменений.
git status - Отображение состояния файлов.
git commit -m "message" - Сохранение текущего stage в локальный репозиторий.
git commit --amend - Изменения последнего коммита (изменить сообщение, добавить новые файлы).
git log - Просмотр истории коммитов.

4.	Какие требования к message коммита?
- Не должен быть пустым.
- Должен отвечать на вопрос, что и зачем было сделано.
- Должен быть лакончиным.
- Желательно писать на английском.

5.	Что такое merge и rebase?
Это способы объединения изменений из одной ветки в другую.
- merge соединяет две ветки и создаёт специальный коммит слияния (merge commit).
Он сохраняет историю и точный порядок событий, безопасен (история не меняется и ничего не перезаписывается), но со временем история становится ветвистой и её становится сложнее читать. Используется для общих и публичных веток (например, main), когда важно сохранить полный контекст работы команды.
- rebase переносит коммиты на новое основание, т.е. берёт коммиты из ветки и по очереди применяет их поверх актуальной вершины другой ветки.
Он полностью переписывает историю: старые коммиты удаляются, а вместо них создаются новые с точно такими же изменениями, но с другими хэшами. Позволяет создавать красивую линейную историю ценой опасности для общего доступа (у других участников команды сломается синхронизация репозитория) и затратами на полное изменения истории. Используется только для локальных, личных веток перед отправкой в общий репозиторий.

6.	Что такое pull request?
Это запрос на слияние изменений из одной ветки кода в другую. В GitHub в окне Pull Request'а в реальном времени другие люди могут оставлять комментарии и замечания, пишется, если слияние приводит к конфликтам и к каким именно, чтобы их можно было просто решить. Применяется только после одобрения уполномоченного лица.
